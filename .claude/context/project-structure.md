# Project Structure

## Root Directory Organization
```
trabant/
├── .claude/           # Claude Code configuration and context
├── Cargo.toml        # Rust project manifest
├── CLAUDE.md         # Development guidelines for Claude Code
├── local/            # Local development tools and binaries
│   └── bin/          # Local tool installations (wasm-pack, etc.)
├── scripts/          # Development and utility scripts
│   ├── bootstrap.sh  # Environment setup script
│   └── generate-fixtures.py  # Reference data generation
├── src/              # Rust source code
│   └── lib.rs        # Main library entry point
└── tests/            # Test suite and fixtures
    └── fixtures/     # JSON test data files
        ├── hotsat1-berlin-passes.json
        ├── hotsat1-omm.json
        └── hotsat1-positions.json
```

## Key Directory Purposes

### `/src/`
- **Primary Purpose**: Rust library source code
- **Entry Point**: `lib.rs` - main library interface
- **Architecture**: Single-file library (currently minimal, ready for expansion)

### `/scripts/`
- **Purpose**: Development workflow automation
- **Pattern**: Shell scripts (.sh) and Python scripts with uv dependencies
- **Key Scripts**:
  - `bootstrap.sh`: Development environment setup
  - `generate-fixtures.py`: Reference data generation using skyfield

### `/tests/fixtures/`
- **Purpose**: Reference data for validation testing  
- **Source**: Generated by Python skyfield library for precision comparison
- **Content**: Satellite orbital data and pass predictions for Berlin location

### `/local/bin/`
- **Purpose**: Local tool installations to avoid global dependencies
- **Managed By**: bootstrap.sh script
- **Contents**: wasm-pack and other development tools

### `/.claude/`
- **Purpose**: Claude Code integration and project management
- **Structure**: Configuration files and context documentation
- **Management**: CCPM system for project context and workflow

## File Naming Patterns
- **Rust Files**: Standard Rust conventions (lib.rs, main.rs, mod.rs)
- **Scripts**: Descriptive names with appropriate extensions (.sh, .py)
- **Fixtures**: Descriptive names indicating satellite and data type (hotsat1-*.json)
- **Config Files**: Standard names (Cargo.toml, CLAUDE.md)

## Module Organization Strategy
- **Current**: Single-file library structure
- **Planned**: Modular organization as complexity grows
- **Pattern**: Standard Rust module hierarchy with clear separation of concerns
